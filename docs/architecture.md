# アーキテクチャ

最終更新: 2026-07-16

## 全体方針

Face Icon MakerはReactで動作するブラウザ完結型アプリである。写真・中間画像・生成PNGは端末内のメモリとCanvasで処理し、アプリのサーバーへ送信しない。

```text
画像選択
  ↓
向き補正・検証・長辺3,000pxへ縮小
  ↓
MediaPipe Face Detector
  ↓
顔選択・2.2倍の自動切り抜き・編集
  ↓
[任意] Real-ESRGAN x4
  ↓
[任意] 選択顔を起点に背景分離
  ↓
スタイル・背景色・形状の描画
  ↓
512 × 512 PNGの保存 / 共有
```

## 主な責務

### UI

- `src/pages`: 各画面とユーザーフロー
- `src/components`: 再利用可能な表示・操作部品
- React state: 画像、検出結果、選択顔、編集設定、処理状態

### サービス

- `imageService.ts`: 入力検証、画像読み込み、向きと縮小
- `faceDetection.ts`: MediaPipe Face Detectorの初期化と複数顔検出
- `cropService.ts`: 顔枠から切り抜き領域を算出
- `superResolutionService.ts`: LiteRT.js / Real-ESRGANによる超解像
- `segmentationService.ts`: 対象人物ベースの背景分離とフォールバック
- `renderPipeline.ts`: 背景、スタイル、形状をCanvasへ合成
- `exportService.ts`: PNG生成、保存、共有

ビジネスロジックはUIへ埋め込まず、サービスとして単体テスト可能にする。

## 画像処理の順序

### 1. 入力

JPEG / PNGだけを受け付け、サイズ・画素数・辺長を検証する。EXIF Orientationを反映し、処理負荷を抑えるため長辺を最大3,000ピクセルへ縮小する。

### 2. 顔検出と切り抜き

MediaPipe Face Detectorで複数の顔枠を取得する。選択顔の枠を約2.2倍へ拡張して正方形化し、髪と頭部を含める。画像端では範囲を画像内へ補正する。

### 3. 超解像

切り抜き元が512ピクセル未満でユーザーが有効化した場合だけ実行する。

- 128 × 128ピクセルのタイルへ分割
- 20%重複させて境界をなじませる
- 各タイルをReal-ESRGAN x4で512 × 512へ推論
- タイルを再構成して4倍の中間画像を生成
- WebGPU優先、WASMフォールバック

超解像は背景分離より先に実行する。輪郭情報を増やした画像をセグメンテーションへ渡し、小さい顔の境界判定を改善するためである。

### 4. 背景分離

選択顔の中心をポイントプロンプトとしてMediaPipe Interactive Segmenter（MagicTouch）へ渡す。モデルの背景側confidence maskを反転して人物マスクを作り、選択顔と連結した成分だけを残す。

初期化・推論に失敗した場合はSelfie Segmenterへフォールバックする。背景除去を使わない場合は、この処理を省略する。

### 5. 描画と出力

背景分離結果、スタイル、背景色、四角形 / 円形をCanvasで合成し、最終的に512 × 512ピクセルのPNGを生成する。超解像はディテール復元用であり、出力寸法を4倍にはしない。

## モデルとランタイム

| 用途 | ランタイム / モデル | 読み込み |
|---|---|---|
| 顔検出 | MediaPipe Face Detector | 必要時 |
| 対象人物の背景分離 | Interactive Segmenter / MagicTouch | 背景変更時 |
| 背景分離フォールバック | Selfie Segmenter | フォールバック時 |
| 超解像 | LiteRT.js / Real-ESRGAN x4 float TFLite | 超解像初回実行時 |

モデルは遅延読み込みし、通常フローの初期表示を阻害しない。超解像モデルは約67 MBであり、初回待ち時間はネットワークとブラウザキャッシュに依存する。

## LiteRTの配布

`@litertjs/core`を利用する。Vite設定で必要なWASM 8ファイルを `/litert/wasm/` へコピーし、実行時に同一オリジンから読み込む。モデルURL、WASMパス、アクセラレータなどは `src/config/superResolution.ts` と環境変数で管理する。

## 非同期処理と障害時の扱い

- モデルの初期化Promiseを共有し、同一モデルの重複ロードを防ぐ
- 超解像処理中は主ボタンをキャンセルへ切り替える
- キャンセル済み処理の完了結果を画面へ反映しない
- WebGPU失敗時はWASM、超解像全体の失敗時は通常解像度へフォールバックする
- Interactive Segmenter失敗時はSelfie Segmenterへフォールバックする
- Object URL、ImageBitmap、Canvasなどの一時リソースは処理後に解放する

## セキュリティとプライバシー

写真データを外部APIへ送信しない。一方で、モデル・WASMは外部または同一オリジンから取得するため、初回利用は完全オフラインではない。将来モデル配信元を変更する場合も、写真をリクエストへ含めないことを維持する。

## テスト戦略

- 単体: 切り抜き境界、タイル分割・再構成、マスク反転・連結成分
- 結合: 超解像→背景分離→描画→PNGの順序とフォールバック
- UI: 進捗、キャンセル、連続操作、レイアウトシフト
- 実機: WebGPU差、Safari制限、低速回線、メモリ圧迫、共有API

同一実機に対する自動化スクリプトは並列実行しない。
