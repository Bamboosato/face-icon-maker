# Face Icon Maker 要件

最終更新: 2026-10-06

本書は現行の実装範囲と品質目標を整理する。性能・互換性・信頼性の目標は、全環境での達成保証を意味しない。未実装・未検証の差分は末尾と[確認記録](documentation-audit.md)を参照。

## 1. 目的

集合写真から自分の顔を選び、プロフィール用PNGアイコンを短時間で作成できるブラウザアプリを提供する。

成功条件は「写真を選ぶ → 顔を選ぶ → PNGを保存する」を30秒以内で完了できることとする。

## 2. 制約

- 画像処理はブラウザ内で完結させる
- 写真・生成画像をサーバーへ送信しない
- バックエンド、データベース、認証、有料APIを使用しない
- スマートフォンを主対象とし、片手操作と大きなタップ領域を優先する
- 高度な画像編集機能より、顔の検出・選択・自動切り抜きを優先する

## 3. 機能要件

### 3.1 写真の読み込み

- JPEG / PNGを受け付ける
- 50 MiB以上（50 × 1024 × 1024バイト）、50メガピクセル以上、一辺12,000ピクセル以上は明示的に拒否する
- ファイル選択とドラッグ＆ドロップに対応する。形式判定はMIMEまたは拡張子で行い、破損などのデコード失敗は読み込みエラーにする
- EXIF Orientationを反映する
- 処理用画像は長辺最大3,000ピクセルへ縮小する

### 3.2 顔の検出と選択

- MediaPipeで複数の顔を自動検出する
- 検出顔に番号付きの選択枠を表示し、選択すると編集画面へ移る
- 検出感度を0.10〜0.95、0.05刻みで調整できる（初期値0.50）。顔選択画面で変更すると再検出する
- 全体画像で感度条件を満たす顔が0件の場合のみ、重複するタイルで再検出し、重複顔をまとめる
- 初回検出で顔が見つからない場合は写真選択画面へ戻る。再検出で0件の場合は顔選択画面を維持し、感度変更・再検出または別写真の選択を可能にする

### 3.3 自動切り抜きと編集

- 選択した顔の検出枠を基準に、約2.2倍の正方形領域を生成する
- 髪や頭部を含め、画像の端では範囲を画像内へ補正する
- 自動切り抜きのサイズは96ピクセル以上を基準にする。ただし画像の短辺が96ピクセル未満なら画像内に収める。手動編集の範囲補正は1ピクセル以上であり、96ピクセルの下限を一律には適用しない
- 元画像上の1:1 Crop枠で位置と大きさを調整し、アイコンのプレビューへ反映できる

### 3.4 見た目の調整

- 形: 四角形 / 円形
- スタイル: 通常 / ピクセル / コミック / ペイント
- ピクセル粒度: Small / Medium / Large（内部の縮小画像は64 / 48 / 32ピクセル）
- ペイント強さ: 0〜100、5刻み（初期値50）
- 背景: 元画像 / 透明 / 単色。単色は4色のスウォッチから選択する
- 背景除去は選択した顔の中心を起点にInteractive Segmenterで対象人物を分離する
- 対象人物と連結していない前景候補は除外する
- Interactive Segmenterが利用できない場合はSelfie Segmenterへフォールバックする
- 両方の背景分離に失敗した場合は元背景を残して描画を継続する。背景分離失敗専用のエラー表示はない

### 3.4.1 アニマルフェイス

- Noneと12種類のプリセットを提供する: Cat / Dog / Fox / Bear / Elephant / Lion / Rabbit / Panda / Raccoon / Tiger / Wolf / Hamster
- 顔選択時にFace Landmarkerの `IMAGE` モードで解析する。参照領域内の最大3顔から選択顔の中心に最も近い候補を利用する
- 処理用画像座標でランドマークを保持し、切り抜き・プリセット変更時は再推論しない
- 顔の大きさ・傾きに合わせてSVG、目元の線、口元の半透明装飾を合成する。画素の局所変形は未実装
- ランドマーク準備中・解析失敗時はプリセット選択を無効にする。解析失敗でも通常の編集・PNG保存を継続できる
- 超解像出力時はランドマーク座標を中間画像へ変換する
- 詳細は[アニマルフェイス要件](animal-face-requirements.md)を参照

### 3.5 超解像

- 切り抜き元が512ピクセル未満の場合に任意で有効化できる
- 256ピクセル未満では推奨状態を表示する
- Real-ESRGAN x4で縦横4倍の中間画像を生成する
- 超解像を背景除去・スタイル処理より先に実行する
- 最終出力サイズは超解像の有無にかかわらず512 × 512ピクセルとする
- 処理中は進捗を表示し、同じ主ボタンからキャンセルできる
- 進捗表示によってボタン群や画面全体が上下に移動しない
- WebGPUを優先し、利用できない場合はWASMへフォールバックする
- 初期化・モデル取得・推論に失敗した場合は通常解像度で保存できる
- WebGPUからWASMへの切り替えはモデルの読み込み・コンパイル失敗時に行う。推論中の失敗は通常解像度での保存へ戻す
- 超解像は保存時だけ実行し、プレビューへは適用しない
- `VITE_SUPER_RESOLUTION_ENABLED=false` の場合は選択肢を表示しない

### 3.6 出力

- 512 × 512ピクセルのPNGを生成する
- スマートフォン判定時は `Share PNG`、それ以外は `Save PNG` とする
- スマートフォンでもファイル共有APIが利用できない、または共有がキャンセル以外の理由で失敗した場合はダウンロードへフォールバックする
- 共有シートのキャンセルではダウンロードを開始しない
- ファイル名は `元の名前_faceYYYYMMDD.png`（端末の日付）とする。禁止文字を置換し、元の名前部分を最大32文字に制限する。空・UUID形式の名前は `face-icon` とする

## 4. 非機能要件

### 性能

- 顔検出開始: 通常環境で3秒以内を目標
- 顔選択の反応: 100ミリ秒以内を目標
- 通常PNG生成: 1秒以内を目標
- 超解像: 端末・ブラウザ・モデルキャッシュ・ネットワークに依存するため、時間固定の合否条件を設けず、進捗とキャンセル手段を保証する

### 信頼性

- 非同期処理の二重起動を防ぐ
- キャンセル後に古い処理結果で画面を更新しない
- モデル処理の失敗を通常保存の失敗へ波及させない
- 画像・Canvas・モデル関連リソースを不要になった時点で解放する

### 互換性

- 最新版Chrome / Edge / Safariを主対象とする
- WebGPU非対応環境でもWASMで超解像を試行できる
- 端末のメモリ不足やブラウザ制限時は、通常解像度で完了できる

### プライバシー

- 写真・切り抜き・生成PNGを外部へ送信しない
- モデルとWASMの取得にはネットワークを利用する
- UI上の説明は「処理はこの端末内で行われる」とし、完全オフラインと誤認させない
- 写真・編集内容・ランドマークを永続保存しない。再読み込みで作業状態は失われる
- manifestとホーム画面用アイコンはあるが、Service Workerとオフライン保証は未実装

## 5. 状態遷移

1. 未選択
2. 画像読み込み中
3. 顔検出中
4. 顔選択
5. 編集
6. 通常保存中、または超解像準備・処理中
7. 保存 / 共有完了

エラーまたはキャンセル時は、画像や編集内容を失わず編集状態へ戻れること。

現行では入力・顔検出エラーは写真選択画面へ戻り、Landmarkerエラーは編集画面を維持する。保存画面から編集へ戻ると編集設定を保持するが、超解像ON/OFFは保存画面の状態のため再入場時にOFFとなる。別の顔を選択するとCropとアニマル設定は初期化し、形・スタイル・背景は保持する。再開始時も検出感度は保持する。

## 6. テスト観点

### 機能観点

- 正常系: 複数顔の検出、任意顔の選択、編集、12種類のアニマル加工、通常保存、超解像保存
- 異常系: 未対応形式、上限超過、モデル取得失敗、WebGPU初期化失敗、推論失敗
- 境界値: 96 / 255 / 256 / 511 / 512ピクセル付近、入力上限、検出感度の上下限
- 状態遷移: 保存中のキャンセル、連続保存、編集へ戻る、最初からやり直す

### 非機能観点

- 低速回線での初回モデル取得
- WebGPUあり / なし、キャッシュあり / なし
- 高負荷・低メモリ端末でのフォールバック
- 非同期処理完了とキャンセルの競合

### データ観点

- 1人 / 複数人 / 顔なし
- 小さい顔、横顔、眼鏡、帽子、髪と背景が近い色
- 人物に接する木や衣服に似た背景
- 画像端の顔、縦長 / 横長、透過PNG

### UI観点

- タップ領域、選択状態、進捗、エラー文言
- 超解像ON/OFFでレイアウトが移動しないこと
- 処理中に主ボタンがキャンセルへ切り替わること
- 円形・透明背景のプレビューと出力一致
- アニマル選択の準備中・失敗時の無効状態と、Noneへ戻す操作
- 超解像前のプレビューと超解像保存後の画質差（完全な画素一致は求めない）

## 7. 受け入れ基準

- デスクトップChromeで基本フローが完了する
- iPhone 13 Pro Maxで超解像ONの保存を過度なストレスなく完了できる
- 背景の木など、選択人物と非連結の誤前景が出力へ残らない
- 超解像の有無で最終PNGの寸法が変わらない
- モデル処理に失敗しても通常解像度で保存できる

## 8. 現行との差分・継続課題

- 選択中の顔枠を強調する要件は未実装。現在は枠を押すと直接編集画面へ移る
- 古い結果の破棄はLandmarkerとプレビューに実装されている。画像準備・顔再検出全体を保護するリクエストID、再検出の完全な二重起動防止は未実装
- キャンセルは超解像開始時・モデル準備後・各タイル開始時に確認する。取得や推論を即時中断する保証、最終タイル後から保存開始までのキャンセル確認はない
- 顔検出・ランドマーク・背景分離の初期化失敗Promiseはページ内に残る。明示的な再初期化・再試行と、リセット時のモデルcloseは未実装
- モデル失敗からの通常保存は超解像とLandmarkerで対応しているが、すべてのCanvas・PNG生成失敗からの復旧を保証するものではない
- 性能目標、ブラウザ互換性、実機での競合・低メモリ動作は継続検証対象。実装状況と検証範囲は[実装・検証タスク](tasks-mvp.md)に分けて記録する
